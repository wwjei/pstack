# Notion 文档

## 这个来源里有什么

- PRD（产品需求文档）
- 技术规格与 RFC
- 架构决策记录（ADR）
- 设计评审的会议记录
- 带领域背景的团队页面
- 事故复盘报告
- 可能解释防御性代码的运行手册
- 定优先级的战略文档

「为什么」在变成代码之前，常以长文形式住在 Notion 里。一个重要功能通常有一篇文档。

## 怎么搜

用 Notion MCP。

1. **用 `notion-search` 做关键词搜索。** 试试：
   - 功能名
   - 目标代码里的关键符号 / 类名
   - 作者账号（设计文档常在代码落地前写好）
   - 错误字符串或用户可见的词
   - 知道代码何时发布时，加时间范围
2. **用 `notion-fetch` 拉候选页面。** 读全文，别只读预览。理由常埋在文档中段。
3. **追反向链接和子页面。** 设计文档常有子页面，放考虑过的备选方案、附录或实现笔记。
4. **查相关数据库。** `notion-query-data-sources` 和 `notion-query-meeting-notes` 能浮出讨论过该决策的会议记录。
5. **搜作者个人空间。** PR 作者若有个人笔记本（有些公司常见），里面可能存着先于代码的探索性思考。

## 这里的好证据长什么样

- 一篇 PRD，其「Problem statement」或「Motivation」小节与目标代码的用途相符
- 一节「Alternatives considered」或「Rejected approaches」
- 一篇复盘报告，点名目标代码是某次事故的修复
- 会议记录里写着「我们决定 X，因为 Y」，且作者/日期范围与 PR 对得上
- 一份认真填过的 ADR 模板（状态、背景、决策、后果）

## 常见坑点

- **过时文档。** 规格常在实现前写好，之后不更新。文档描述的计划可能已经变了。与实际 PR 交叉核对。
- **文档与现实漂移。** 规格可能写「我们要做 X」，代码实际做 Y。标出分歧。综合者会把矛盾摆出来。
- **模板套话。** 有些组织要求「Why」小节，结果填的都是空话。找具体的内容。
- **没被链接的文档。** 最相关的文档可能哪里都没链它。宽泛的关键词搜索有用。
- **多份草稿。** 一个主题有多篇文档时，找定稿或最近更新的那篇。核对日期。
- **受限页面。** 访问不了某个页面时，记成缺口。

## 返回什么

每篇相关文档，附上：
- 标题与 URL
- 作者与最后更新日期
- 动机文字（逐字引用），带页面/小节位置
- 相关的链接页面（方便综合者做引用出处）
- 文档是定稿还是草稿
