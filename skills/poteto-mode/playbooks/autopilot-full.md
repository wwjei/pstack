### 全自动驾驶

**结论归你管，PR 不归你管。每个 PR 由一个所有者从构建跑到合并，没有你的干净 swarm 结论，什么都不许合并。** 适用于「autopilot this queue」「full autopilot」以及每个 PR 一个所有者的项目。Orchestrate 跑的是常设项目，协调器自己落地已验证的工作，子代理从不合并。这里每个 PR 的所有者把整个生命周期扛到合并，根只保留验证、副签和审计。

1. **标记操作者的条目，遵守先陈述后等待。** 操作者点名的条目留在操作者手里。操作者审查并点击，任何所有者都不合并它。操作者要求陈述协议或项目时，给出陈述就停下。只有操作者明确放行，执行才开始。
2. **每个 PR 派一个所有者，扛全生命周期，尽早留痕。** 整个项目只定一次托管平台。默认 GitHub CLI（`gh`）。`command -v origin` 成功且 Origin 能解析这个仓库时，PR 的创建、编辑、查看、监视、合并都用 `origin pr ...`。否则留在 `gh`，记下这次回退。绝不要求 Graphite（`gt`）。每个 PR 一个 `delegate_task` 子代理当所有者，负责构建、首次推送、开就绪 PR、在真实产物上自证（**prove-it-works** 原则技能）、按 `../references/bugbot-triage.md` 怀疑式分诊 Bugbot、去 AI 味（`pstack:deslop`）、`/no-comments`（**no-comments** 技能）、rebase 到当前主干、盯跑循环跑到绿（`playbooks/babysit.md`），以及合并本身。约 15 分钟内，每个所有者按 **show-me-your-work** 技能开一份 `decisions.tsv` 决策日志，推送第一个分支快照，把 PR 开成就绪，绝不开草稿。之后每完成一个可验证单元，所有者就再推一次分支（钩子开着，WIP 提交也行）。先开 PR 再自证，让 URL、决策和检查构成一条持久的痕迹。`decisions.tsv` 不提交，随报告一起交回。子代理一启动，所有者就把它的 ID、预期运行时长（至少取同类过往最长的一次运行）和状态记进同样保管的 `children.tsv`。无论主干有没有漂移，所有者都在代码就绪报告和盯跑之前做第一次 rebase。修复轮里，所有者保持那个合并基。只有这几种情况才再次 rebase：合并准备（第 5 步）、`git merge-tree` 与主干冲突、来自主干改动的 CI 失败、已知的同文件并发改动落地。发布的代码定稿后，即去 AI 味和 `/no-comments` 之后，报告代码就绪的头提交 SHA。之后每次改变补丁的推送也报告 SHA。随后自证、CI、盯跑与 swarm 并行跑。自证、CI、盯跑都完成后，所有者报告合并就绪，附上头提交 SHA。启动一轮的推送之前，先跑仓库的 AGENTS.md 文件和规则为所碰路径点名的审查前检查。在已提交的头提交上跑。钩子通过不算证明。每次 rebase 要发布时，先做 `ls-remote` 检查，再用 `git push --force-with-lease` 推所有者自己的分支。绝不强推共享分支。合并是所有者唯一不能单独做的一步。第 4 步给它设关卡。
3. **所有者真并行，绝不堆叠。** PR 自包含时多个所有者同时跑：一个分支一个写者，文件互不相交，跨 PR 漂移靠 rebase 吸收。只有真正重叠的工作才串行。自包含的 PR 直接从 main 开分支，有先后依赖的工作先合并再开分支。一个例外：必须拆分真正相互依赖的改动的所有者，可以持有一条短的私有基分支堆叠。
4. **每一轮合并之前都 swarm 验证。** 一轮从所有者的代码就绪头提交 SHA 开始，之后每次改变 PR 补丁的推送也各起一轮。只改措辞不需要新一轮。在那个 SHA 上，按 **swarm** 技能并行分发独立验证器，汇总成一个结论。合并需要补丁与合并就绪头提交一致的那一轮给出干净结论。下结论之前先审计合并就绪报告里的凭据。泳道如下：在那个 SHA 上重跑关卡。在改动碰到的真实界面上实跑证明承重行为（UI 用 `browser_navigate` 和浏览器工具，CLI 用 `terminal`，没有现成工具就点名一个驱动器）。审计 diff，不信 PR 正文。审计拆成两条以上审查泳道，带完整任务说明。每条泳道一个主焦点，比如使用方与主干对齐、生命周期与竞态、数据与配置安全。**对主干的回归泳道。** 在当前主干上跑同一个承重场景。主干没有这个功能，就记下这个事实，改为对 diff 新增的行为加上用户等待的终态设关卡，别假装主干能跑出来。实跑泳道是底线，缺了它的结论不干净。没有根的干净结论就不合并。泳道返回后，只有拿得出来的问题才阻塞 PR：头提交上的一次失败运行，或被 PR 改错的一行文档。PR 的基本来就有的问题，无论来自主干还是堆叠里它下面的 PR，都不阻塞，除非 PR 复制了它或新碰到了它。只有用户会撞上的 bug、失败的关卡、错误的发布文档才阻塞，其余都进后续 PR。把阻塞的发现项打包成一次向前修复发给所有者。每条行为类发现项，要求一个覆盖同一缺陷所有位置的先红测试。测试展示不了缺陷的地方，改为要求复现凭据。把该缺陷加进下一轮的审查任务说明。新头提交配新 swarm 和新结论，按 `playbooks/shipping.md` 的 patch-id 规则仍然有效的泳道结果除外。
5. **拿到干净结论，所有者合并，新所有者接下一项。** 所有者只从刚 rebase 到主干的头提交合并。合并准备绝不早于一轮泳道启动，并以合并前紧挨着的一次 rebase 到当前主干收尾。合并准备的 rebase 之后，所有者报告新头提交 SHA。合并前 CI 必须在这个头提交上通过，本轮结论是否仍成立由 patch-id 规则裁定。这个头提交绿了、且按 `playbooks/shipping.md` 的 patch-id 规则其 patch-id 与结论的一致之后，主干再动也不强制再 rebase。合并前紧挨着，抓取主干，检查头提交对当前主干的 `git merge-tree` 干净。再检查 `git diff --name-only $(git merge-base HEAD origin/main) origin/main` 里的路径，没有一条是本 PR 改动的路径，也没有一条决定本 PR 跑哪些 CI 的路径，比如仓库的 CI 配置路径。任一检查失败，就再 rebase，报告新头提交 SHA，等 CI 在它上面通过，重复这些检查。新头提交作废旧结论，除非 patch-id 不变。所有者通过定下的托管平台 squash 合并自己的 PR，然后返回。新所有者按 poteto-mode 的「委派」小节从队列接下一个自包含条目。操作者的全自主授权加上根的干净结论，就是合并授权，单靠盯跑永远没有这个授权。操作者点名的条目停在合并就绪，等操作者点击。
6. **运行根层。** 真正新上调一个钉死的关卡或预算值（CI 只允许收紧的限制），需要你重新副签，且只在验证器给出证明之后才给。操作者的授权或常设指令覆盖审批时，这个副签就是审批。所有者按工具的审批契约允许的形式记录它，附上指向根副签的指针。一条泳道对照该副签检查记录。根绝不给出或绕过托管平台强制的审批。吸收已经落在 main 上的值属于漂移，不是上调。每小时对所有所有者跑一轮审计巡检。操作者放行后，布设 `cronjob 1h`，提示词就是跑这轮巡检。绝不把节拍交给记忆或会丢的完成通知。每轮巡检都用 `git show origin/main:pstack/skills/poteto-mode/playbooks/autopilot-full.md` 从主干重读本手册，对照它审计运行。漂移在这轮巡检里修。用通用的存活或状态检查探每个所有者，收齐决策日志。只有副作用才算进度：提交、推送、PR 或检查的增量、存档的报告。泳道报错，或超过预期运行时长还没有副作用，按卡死处理。立即让它停手，派替代者。别等它体面返回。巡检按第 2 步要求的已推分支和决策日志评判所有者，代理无法开启一轮对话的所有者直接换掉。每轮巡检还对项目的代理清单（平台有的话）和每个所有者的 `children.tsv` 跑泳道卡死测试。无论停止是否生效，根都让所有者把每个卡死的子代理记为卡死，工作还需要就换掉。替代者再卡死，同样步骤再来一遍。所有者做不到时，根把这两步都做了。卡死既不证明工作完成，也不取消工作。合并攒成批时，跑一轮复盘和合并后的机器人评论清扫。只有委派的工作全部清空才结束巡检，最后一次合并之后也一样。
7. **操作者喊停，立即停手。** 操作者的暂停或停手令立即作为零写入命令传达到每个所有者。所有者按住任务说明，直到操作者放行。

**回复：** 队列，含每个 PR 的所有者、状态、头提交 SHA。每个结论及产出它的 swarm。合并了什么，每个新所有者接了什么。给出的副签及理由。还开着的操作者关卡。收齐的决策日志放在哪。
